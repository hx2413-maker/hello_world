# Campus content sources

The app uses three public, read-only sources. No source account or paid API key is required.

| Feature | Source | Refresh |
| --- | --- | --- |
| Template library | [Imgflip's documented `get_memes` API](https://imgflip.com/api) | Weekly on Monday at 12:00 UTC; the cached catalog also expires after seven days |
| Campus idea | [Columbia News](https://news.columbia.edu/) | Daily at 11:00 UTC; the cached source also revalidates after six hours |
| Holiday inspiration when campus news is unavailable | [Nager.Date's public holiday API](https://nagerholidays.com/api) | The same daily campus-idea refresh and six-hour cache |

`vercel.json` schedules both requests against `/api/refresh-content`. Set a random server-only `CRON_SECRET` in the Vercel Production environment. Vercel automatically sends it in the `Authorization: Bearer …` header. The handler rejects requests if the secret is missing or incorrect. Local testing may use the same variable in `.env.local`; never commit it. The schedules fit Vercel Hobby's once-per-day maximum frequency per job. Exact execution time can vary within the scheduled hour.

The refresh handler expires the appropriate Next.js Data Cache tag and requests the source again. A campus-idea refresh succeeds when either a recent news story or a public holiday is available; it returns 502 only when both sources fail or have no eligible result. Template refresh returns 502 when its provider fails. Authenticated refresh responses include bounded diagnostic status codes and the selected provider, without secrets or raw provider content. Cache-based refresh is also available on page visits, so the application still works between scheduled runs. The template gallery shows the upstream response's date, when available, as its catalog snapshot date, not a claim of real-time popularity.

Columbia's homepage currently publishes a `highlights_data` JSON array with headline, category, article URL, and publication timestamp. The implementation parses that JSON without executing its enclosing script, with dated article teasers as a secondary parser. This was checked against the live page on October 30, 2026. The `/rss.xml` path currently serves the homepage rather than a feed, so it is intentionally not used. Only articles from `news.columbia.edu`, no more than 21 days old, are eligible. Campus & Community stories take priority, followed by University News, Photo of the Week, and Office Hours. The prompt links to the original story and exposes publication and retrieval dates.

Production verification found that Columbia News returns HTTP 403 to Vercel while accepting local requests. The app does not bypass that restriction. It requests Nager.Date in parallel and uses the next eligible U.S. public holiday if Columbia news is unavailable. The [documented API](https://github.com/nager/Nager.Date) supplies dated JSON at `https://nagerholidays.com/api/v3/publicholidays/YEAR/US`. The parser accepts national or New York public holidays in the next 93 days, uses the New York calendar day, and handles year rollover. The idea links to Nager.Date's U.S. calendar and explicitly identifies it as a holiday source, not Columbia's class schedule. It never claims that campus classes are cancelled. If neither source is available, the app labels a built-in campus idea as a fallback.

Template images are loaded only from exact `i.imgflip.com` URLs returned by the catalog. The generator receives a template ID, never a client-provided download URL. Server downloads reject redirects, unsupported MIME types, mismatched raster signatures, and streamed bodies over 2 MiB. The normal meme image decoder still validates dimensions, animation limits, and image content before sending sanitized media to Gemini. The library credits Imgflip and links back to its catalog.

Relevant verification: `node --test tests/content-sources.test.mjs` covers source URL boundaries, malformed provider data, news and holiday dates, New York day boundaries, year rollover, response size limits, and raster signatures. Cold campus-source requests run in parallel with a 3.5-second timeout each; authenticated scheduled refreshes allow 10 seconds. The template catalog timeout is 5 seconds.
